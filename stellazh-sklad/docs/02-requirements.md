# 2. Требования

## Функциональные

| ID | Требование |
|---|---|
| FR-1 | Справочник позиций: добавление, поиск (по названию, артикулу, ячейке, без учёта регистра и буквы «ё»), фильтры по категории и статусу, сортировка, удаление |
| FR-2 | Справочник контрагентов: поставщики и покупатели, поиск, изменение, удаление |
| FR-3 | Приходная накладная с несколькими строками: черновик, проведение |
| FR-4 | Акт списания с несколькими строками, причиной списания и покупателем (при отгрузке) |
| FR-5 | Контроль остатка: списать больше, чем есть, нельзя; документ проводится целиком или не проводится вовсе; предупреждение при падении ниже минимума |
| FR-6 | Правка проведённого документа (откат остатков и повторное проведение), отмена документа |
| FR-7 | Журнал операций: каждая строка проведённого документа с номером документа и остатком после |
| FR-8 | Статусы позиций («В наличии», «Заканчивается», «Нет на складе») и сводка по складу |

## Нефункциональные

| ID | Требование |
|---|---|
| NFR-1 | Работает в браузере без сервера и установки (открыть `index.html`) |
| NFR-2 | Данные хранятся только локально (`localStorage`), в репозитории нет паролей и персональных данных; контрагенты в демо-данных вымышленные |
| NFR-3 | Сообщения об ошибках на русском языке, указывают конкретную строку и причину |
| NFR-4 | Интерфейс адаптивен (компьютер и телефон), поддерживает тёмную тему |
| NFR-5 | Логика отделена от интерфейса и проверяется автоматическими тестами без браузера |

## Пользовательские сценарии

**Сценарий 1. Приёмка товара.** Кладовщик открывает «Документы → Приходная накладная», выбирает поставщика,
добавляет строки «позиция — количество», сохраняет черновик и проводит. Остатки растут, в журнале появляются записи.

**Сценарий 2. Отгрузка покупателю.** Кладовщик создаёт акт списания с причиной «Отгрузка покупателю», выбирает покупателя
и строки. Если по какой-то строке не хватает товара, она подсвечивается красным и документ не проводится.
После проведения система предупреждает, какие позиции опустились ниже минимума.

**Сценарий 3. Исправление ошибки.** Кладовщик заметил неверное количество в проведённой накладной, нажимает
«Редактировать», остатки откатываются, он исправляет строку и проводит документ снова.

## Критерии приёмки

| Требование | Критерий | Тест |
|---|---|---|
| FR-3 | После проведения накладной остатки выросли на количество в строках, в журнале есть записи | T-01 |
| FR-4 | После проведения акта остатки уменьшились | T-02, T-14 |
| FR-5 | При нехватке остатка документ не проводится, остатки и журнал не меняются | T-07, T-10, T-18 |
| FR-6 | После правки и повторного проведения остатки пересчитаны верно; если товар уже израсходован, правка запрещена | T-04, T-15, T-16 |
| FR-1 | Поиск «ПЛЁНКА» находит «Стрейч-плёнка» | T-05 |
| FR-2 | Дубль контрагента отклоняется | T-13 |
| Проверка ввода | Пустое название, нет строк, нет поставщика, дата в будущем отклоняются | T-06, T-09, T-12, T-17 |
